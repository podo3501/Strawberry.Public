# UIVisualizer (`Game/Visualizer/UIVisualizer`)

- 역할: 같은 JSON에서 만든 하나의 UI를 Claude에게는 텍스트(피드백 데이터)로, 사람에게는 화면(DxRender)으로 보여 준다. 편집 도구가 아니다. JSON을 고치는 쪽은 Claude이고 사람은 결과를 눈으로 확인한다.
- 텍스트와 화면은 **같은 UI 인스턴스**에서 나온다. 레이아웃 계산이 한 곳에서만 일어나야 화면과 텍스트가 어긋나지 않는다.
- 피드백 생성 코드는 UI 모듈 쪽에 둔다 (`DxRender`/`DxInput`에 의존하지 않는다). `Game/App`은 이 모듈을 조립해 F1 모드로 켜는 얇은 실행 파일이다.
- 폴더는 역할별로 나눈다: `Layout/`(JSON 읽기와 다시 읽기, 이름과 핸들 변환), `Selection/`(위젯 선택, 선택 정보 전달, 윤곽선과 번호. 이들을 묶는 `SelectionFeed`), `History/`(수정 이력), `Move/`(키보드 미세 이동), `Edit/`(이력과 미세 이동을 묶어 JSON을 바꾸는 `LayoutEditor`), `Input/`(여러 기능이 함께 쓰는 키 조회), 루트(전체를 조립하는 `UIVisualizer`와 상태 표시). 새 기능은 맞는 폴더에 넣고, 어디에도 안 맞으면 새 폴더(`History/` 등)를 만든다. 모듈 이름은 폴더와 무관하게 `UIVisualizer.<파일 이름>`이다. 테스트도 같은 폴더 구조를 따른다.
- 이 모듈의 테스트는 `Testing/Game/Visualizer/UIVisualizer-Test`에 있다 (`Test_UIVisualizer.bat`).
- 새 기능은 처음부터 별도 파일로 만든다.
- Claude에게 주는 피드백은 콘솔이 아니라 **파일**로 출력한다. 루트의 요약 파일(전체 요약과 어느 파일을 보면 되는지 가리키는 포인터)과 주제별 폴더의 상세 파일로 나눠서, Claude가 요약만 읽고 필요한 곳만 따라 들어가게 한다. 항목은 한 줄에 한 가지로 쓰고(Grep 가능), 매번 같은 위치에 덮어쓰며, 위젯 경로와 원본 JSON 파일 이름을 함께 적는다.

## 작업 방식 (사람과 Claude의 분담)

구현 순서와 진행 상태는 `Archives/Todo.txt`가 기준이다. 아래는 지켜야 할 설계 원칙이다.

- **분담**: 사람은 화면을 보고 잘못된 곳만 자연어로 말한다 (렌더링이 이상한지, 모양이 어색한지 눈으로 판단하는 것은 사람의 역할이다). Claude는 JSON을 고친다. 스크린샷은 만들지 않고 Claude가 먼저 요청하지도 않는다. 필요하면 사람이 말한다.
- **JSON이 유일한 기준**: 도구는 JSON을 읽어 그리고, 파일이 바뀌면 자동으로 다시 읽는다. 저장 버튼은 없다. 도구 자신이 쓴 변경(미세 이동, 되돌리기)은 쓴 직후에 한 번 바로 읽고, 그 뒤 자동 다시 읽기가 같은 변경을 또 읽지는 않는다.
- **편집 UI 없음**: 속성 패널 같은 값 편집은 두지 않는다. 사람의 직접 조작은 선택한 위젯의 키보드 미세 이동뿐이다 (화살표 1px, Shift+화살표 8px)과 Ctrl+Z/Ctrl+Y 되돌리기와 다시 실행. 이동한 오프셋은 키를 누르는 동안 메모리의 위젯에만 반영해 화면에 바로 보여 주고, 화살표를 모두 뗀 뒤 0.5초가 지나면 JSON에 한 번만 쓴다(`UIVisualizer.WidgetNudger`). 그래야 길게 옮긴 것이 이력의 한 단계가 된다. 선택 정보 파일도 쓸 때가 되어서야 새 위치로 다시 쓴다(그 사이에 보낸 메시지에는 옮기기 전 위치가 붙지만 JSON도 아직 그 값이다). 쓴 파일은 바로 다시 읽어 화면이 항상 JSON에서 나오게 하고(이력에도 이때 한 번 쌓인다), 고른 위젯은 되돌리기처럼 경로로 다시 고른다. 아직 쓰지 않은 이동이 있을 때 Ctrl+Z를 누르거나 F1로 모드를 끄면 먼저 쓴다. 쓰기 전에 다른 쪽(Claude)이 JSON을 고쳤다면 덮어쓰지 않고 옮긴 것을 버린 채 그 파일을 읽는다. 앵커/오프셋이 아니라 컨테이너(Stack, Group 등)가 배치하는 자식은 오프셋으로 움직일 수 없어 건너뛴다(오프셋을 바꿨을 때 화면 위치가 그대로이면 되돌려 놓는다).
- **위젯 이름**: JSON의 각 위젯에 `name`을 두고 형제끼리 겹치지 않게 한다. 이름이 없는 위젯은 `종류#순서`로 임시 표기한다 (순서가 바뀌면 달라지므로 중요한 위젯에는 이름을 붙인다).
- **픽과 선택**: 위젯 고르기는 두 단계다. 클릭은 픽(후보)이고, C 키가 픽한 위젯을 선택한다 (`UIVisualizer.WidgetSelection`). 클릭한 자리의 위젯 체인(가장 안쪽 위젯부터 바깥쪽 조상까지)에서 같은 곳을 계속 클릭할 때마다 한 칸씩 조상으로 올라가고 맨 위에서 한 번 더 클릭하면 가장 안쪽으로 돌아온다. 버튼 안의 글자 대신 버튼을 고르려면 한 번 더 클릭해 올라간 뒤 C를 누른다. 위젯이 없는 빈 곳(루트만 있는 바닥)을 클릭하면 픽이 취소되고 창이 닫힌다. 픽은 체인에서 현재 픽을 가운데에 두고 최대 5개를 "픽 창"(위젯 이름, 없으면 종류가 적힌 직사각형)으로 보여 준다. 안쪽 위젯부터 위에서 아래로 쌓고(창 폭은 이름 글자 폭에 맞추고 최소 폭이 있다, 창 사이는 4px) 마지막으로 클릭한 마우스 위치에서 오른쪽 아래로 뻗으며(화면을 넘으면 안쪽으로 민다), 현재 픽의 창에는 1px 주황 테두리를 두르고 화면의 그 위젯은 밝은 회색 반투명 면(알파 0.22)으로 덮는다. 픽이 있을 때 마우스 휠을 위로 굴리면 안쪽(자식), 아래로 굴리면 바깥쪽(조상)으로 한 칸씩 옮기고 끝에서 멈춘다(순환 없음). 처음과 끝 가까이에서는 창이 멈추고 현재 픽이 가장자리로 움직인다. 선택하면 픽 창은 닫히고 선택한 위젯에만 번호와 같은 밝은 회색 반투명 면이 남는다. 이미 선택한 위젯을 픽하고 C를 누르면 해제된다. Esc는 픽이 있으면 픽만 취소하고, 없으면 선택을 모두 비운다. 픽만 한 위젯은 옮기기와 선택 정보 파일의 대상이 아니다. 면과 창 배경은 `Graphics/Sprite/white.png`(흰색 한 칸)에 틴트로 색을 준다. 선택의 면을 먼저, 픽 창을 가장 나중(가장 위)에 그린다.
- **선택과 전달**: 위젯을 선택하면 화면의 그 위젯 옆에 번호(1, 2, ...)를 그리고, 선택이 바뀔 때마다(C로 선택/해제, Esc, F1, JSON 다시 읽기) `Testing/Resource/.visualizer/Selection.txt`(git에서 제외)를 덮어쓴다. 머리줄에 시각과 JSON 파일 이름을 적고, 아래에 위젯 하나가 한 줄로 번호, 경로(이름을 `/`로 이음, 이름 없으면 `종류#부모 안 순서`), 종류, `screen=x,y,wxh`, `offset=x,y`를 탭으로 적는다 (`UIVisualizer.SelectionReport`). 모드 전체(F1, 다시 읽기)는 `UIVisualizer.UIVisualizer`가 부품(`LayoutLoader`, `SelectionFeed`, `LayoutEditor`, `StatusOverlay`)을 조립해 맡고, App은 서비스 조립과 프레임 루프만 한다. 사람은 화면의 번호로 말하고(예: "1번은 왼쪽으로, 2번은 위로"), Claude는 선택 정보 파일에서 번호를 위젯으로 바꾼다. 번호는 메시지를 보낼 때마다 1번부터 새로 시작한다. 메시지를 보내는 시점에 훅(`.claude/hooks/AttachSelection.sh`, `UserPromptSubmit`)이 선택 정보를 Claude의 입력에 자동으로 넣고 파일을 지운다. 위젯이 없거나 파일이 없으면 아무것도 붙이지 않는다. 앱은 모드 중 선택이 있는데 파일이 없어진 것을 `UIVisualizer.SelectionHandoff`로 알아채 선택을 비우고 "선택 없음"으로 파일을 다시 쓴다 (파일을 지우는 것이 "보냈다"는 신호이고 따로 신호 파일은 없다). 클립보드 복사는 하지 않는다.
- **수정 이력**: JSON을 성공적으로 읽을 때마다 파일 내용 전체를 한 버전으로 메모리에 쌓는다(`UIVisualizer.LayoutHistory`, 최대 50개, 같은 내용은 기록하지 않는다). 사람이 직접 옮긴 것이든 Claude가 고친 것이든 가리지 않고 똑같이 한 버전이 되므로 Claude는 JSON을 고치기 전에 따로 복사하지 않는다. 모드 중 Ctrl+Z는 한 단계 전 버전을 JSON 파일에 쓰고 다시 읽으며, Ctrl+Y(또는 Ctrl+Shift+Z)는 다시 실행한다. 되돌리기로 쓴 파일은 이력에 다시 기록하지 않고, 되돌린 뒤 JSON을 새로 고치면 다시 실행 기록은 버린다. 다시 읽으면 위젯이 새로 만들어지므로 되돌리기 전에 고른 위젯은 경로로 기억했다가(`UIVisualizer.WidgetPathFinder`) 같은 경로의 위젯을 다시 고르고, 없어진 위젯은 건너뛴다. 앱을 끄면 이력은 사라지며 그 뒤는 git이 맡는다. 짧은 시간에 여러 번 JSON을 쓰는 기능(키보드 미세 이동)은 입력이 멈춘 뒤 한 번만 쓰도록 묶어서 이력이 한꺼번에 쌓이지 않게 한다.
- **확장 (보류)**: 캐릭터 위치, 상점 위치 같은 다른 영역도 같은 방식(선택, 번호, JSON 수정, 키보드 이동)으로 다루고, 영역을 골라 들어가고 돌아오게 한다. 이때 선택/번호/선택 정보/이력/다시 읽기는 영역과 무관한 공통 부분으로 두고, 그리기와 선택 대상 목록과 이동 방법만 영역별로 둔다.
