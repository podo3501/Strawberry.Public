# 테스트 코드 규칙

- **중복 없이 작성한다.** 기존 테스트와 겹치면 공통 부분을 리팩토링하거나 중복된 테스트를 삭제한다.
- **한글 주석**: 각 테스트(`TEST_F` 등) 위에 "무엇을 확인하는 테스트인지" 한글 한두 줄 주석을 단다. 사용자가 테스트 목록을 훑어볼 때 의도를 바로 알 수 있게 하기 위함이다. (CLAUDE.md의 "테스트 언급 금지"는 프로덕션 코드 주석과 커밋 메시지에 대한 규칙이며, 테스트 코드 안의 설명 주석과는 별개다.)
- **수치로 정확히 검증한다.** "뭔가 그려졌다" 같은 느슨한 검증보다 좌표/크기/개수를 정확히 확인한다. 대신 기대값은 규칙에서 계산해서 쓰고(예: `패딩 + 바이트 수 × 글자 폭`), 반복되는 상수는 한 곳에 이름을 붙여 모은다.
- **깨진 테스트의 기대값을 실제 출력에 맞춰 고치지 않는다.** 먼저 코드의 버그인지 의도한 변경인지 구분하고, 의도한 변경일 때만 규칙에 맞게 기대값을 고친다.
- **화면에서 눈으로 보는 확인은 사용자가 한다.** 사용자가 알려 주는 버그는 가능하면 재현하는 테스트를 먼저 추가한 뒤 고친다.
- **테스트를 위한 접근 확장 금지**: 테스트를 위해 함수를 `public`으로 만들거나 공개(export)하지 않는다.
