# 테스트 코드 규칙

- **중복 없이 작성한다.** 기존 테스트와 겹치면 공통 부분을 리팩토링하거나 중복된 테스트를 삭제한다.
- **한글 주석**: 각 테스트(`TEST_F` 등) 위에 "무엇을 확인하는 테스트인지" 한글 한두 줄 주석을 단다. 사용자가 테스트 목록을 훑어볼 때 의도를 바로 알 수 있게 하기 위함이다. (CLAUDE.md의 "테스트 언급 금지"는 프로덕션 코드 주석과 커밋 메시지에 대한 규칙이며, 테스트 코드 안의 설명 주석과는 별개다.)
- **수치로 정확히 검증한다.** "뭔가 그려졌다" 같은 느슨한 검증보다 좌표/크기/개수를 정확히 확인한다. 대신 기대값은 규칙에서 계산해서 쓰고(예: `패딩 + 바이트 수 × 글자 폭`), 반복되는 상수는 한 곳에 이름을 붙여 모은다.
- **깨진 테스트의 기대값을 실제 출력에 맞춰 고치지 않는다.** 먼저 코드의 버그인지 의도한 변경인지 구분하고, 의도한 변경일 때만 규칙에 맞게 기대값을 고친다.
- **화면에서 눈으로 보는 확인은 사용자가 한다.** 사용자가 알려 주는 버그는 가능하면 재현하는 테스트를 먼저 추가한 뒤 고친다.
- **사람이 판단하는 테스트(User)와 Claude가 돌리는 자동 테스트(Agent)를 나눈다.** 구분은 폴더가 아니라 파일 이름 끝(`-User`, `-Agent`), 네임스페이스 맨 앞(`User::`, `Agent::`), 묶음(픽스처) 이름 끝(`...User`, `...Agent`)으로 한다. 새 테스트에는 `T` 접미사를 쓰지 않는다. User는 코드로 확인할 수 없는 것(실제로 들리는가, 보이는가)만 최소로 남기고 시작할 때 무엇을 확인해야 하는지 한 줄 출력한다. 상태, 개수, 순서 같은 논리는 Agent로 확인한다.
- **테스트 폴더는 시험하는 소스 구조를 그대로 따른다.** (`Testing/Runtime/SDLAudio-Test/SDLAudio/Static/`은 `Runtime/SDLAudio/Static`을 시험한다.) User/Agent 폴더는 두지 않는다. 공용은 `Doubles/`(가짜: `Fake...`, `InMemory...`)와 `TestSupport/`(테스트 데이터 만들기)에 둔다. 새 `.cpp`/`.ixx`는 `.vcxproj`와 `.filters`에 폴더와 같은 이름의 필터로 등록한다.
- **테스트 네임스페이스는 `역할::시험하는 소스 프로젝트 이름 + Project`로 짓는다.** (예: `Agent::SDLAudioProject`, `User::ServiceProject`) 폴더는 네임스페이스에 넣지 않고, 한 테스트 프로젝트에서 같은 역할의 테스트는 한 네임스페이스에 모은다. 테스트 이름이 실제 클래스(`Widget`, `Voice` 등)와 충돌하지 않게 하려는 규칙이다. 같은 모듈의 다른 파일과 이름이 겹치지 않게(모듈 안의 이름은 링크가 겹친다) 파일 안에서만 쓰는 도우미는 이름 없는 네임스페이스에 두고, 여러 파일이 쓰는 도우미는 역할 네임스페이스 바로 아래(`Agent`)에 둔다. `TEST`/`TEST_F`는 네임스페이스 밖에 두어도 된다. 아직 정리하지 않은 테스트 프로젝트(UI, 입력, 렌더, 에셋)는 예전 방식(`<폴더 이름>Dir`, 실제 디렉터리 구조와 1:1, 예: `GameDir::WidgetDir`)이 남아 있고, 그 프로젝트를 정리할 때 이 규칙으로 바꾼다.
- **테스트를 위한 접근 확장 금지**: 테스트를 위해 함수를 `public`으로 만들거나 공개(export)하지 않는다. 모듈의 비공개 클래스를 시험할 때는 `export`를 추가하는 대신 테스트 `.cpp`를 대상 모듈의 구현 유닛(`module 대상모듈;`)으로 쓴다.
- **오디오 Agent 테스트는 소리 장치 없이 돈다.** `Test_Audio.bat`이 `SDL_AUDIODRIVER=dummy`를 설정하고, 장치로 나가는 소리가 필요하면 `SDL_SetAudioPostmixCallback`으로 가로채서 크기를 확인한다.
