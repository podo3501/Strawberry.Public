# 테스트 코드 규칙

- **중복 없이 작성한다.** 기존 테스트와 겹치면 공통 부분을 리팩토링하거나 중복된 테스트를 삭제한다.
- **한글 주석**: 각 테스트(`TEST_F` 등) 위에 "무엇을 확인하는 테스트인지" 한글 한두 줄 주석을 단다. 사용자가 테스트 목록을 훑어볼 때 의도를 바로 알 수 있게 하기 위함이다. (CLAUDE.md의 "테스트 언급 금지"는 프로덕션 코드 주석과 커밋 메시지에 대한 규칙이며, 테스트 코드 안의 설명 주석과는 별개다.)
- **수치로 정확히 검증한다.** "뭔가 그려졌다" 같은 느슨한 검증보다 좌표/크기/개수를 정확히 확인한다. 대신 기대값은 규칙에서 계산해서 쓰고(예: `패딩 + 바이트 수 × 글자 폭`), 반복되는 상수는 한 곳에 이름을 붙여 모은다.
- **`Assert`는 호출하는 쪽의 실수 중 결과를 정할 수 없는 입력에만 쓴다.** `Assert`가 걸리면 Debug에서 멈춰 시험할 수 없고, 시험은 호출하는 쪽이 넘기는 값까지는 지켜 주지 못하기 때문이다. 함수를 시험하면서 `Assert`마다 이렇게 판단한다: (1) 잘못된 입력에도 정해진 결과를 줄 수 있으면 그 결과를 정의하고 `Assert`를 빼고 시험한다 (예: 범위를 넘는 니블은 0). (2) 실행 중 실패할 수 있는 작업이면 `bool`과 `Logger::Error`로 바꾸고 시험한다. (3) 컴파일 때 알 수 있는 값이면 `static_assert`로 바꾼다. (4) 어느 쪽도 아니면(0으로 나누기, 2의 거듭제곱이 아닌 정렬처럼 결과가 없는 경우) `Assert`를 남기고 그 경로는 시험하지 않는다. 파일이나 설정에서 읽은 값에는 `Assert`를 쓰지 않는다.
- **깨진 테스트의 기대값을 실제 출력에 맞춰 고치지 않는다.** 먼저 코드의 버그인지 의도한 변경인지 구분하고, 의도한 변경일 때만 규칙에 맞게 기대값을 고친다.
- **화면에서 눈으로 보는 확인은 사용자가 한다.** 사용자가 알려 주는 버그는 가능하면 재현하는 테스트를 먼저 추가한 뒤 고친다.
- **사람이 판단하는 테스트(User)와 Claude가 돌리는 자동 테스트(Agent)를 나눈다.** 구분은 폴더가 아니라 파일 이름 끝(`-User`, `-Agent`), 네임스페이스 맨 앞(`User::`, `Agent::`), 묶음(픽스처) 이름 끝(`...User`, `...Agent`)으로 한다. 새 테스트에는 `T` 접미사를 쓰지 않는다. User는 코드로 확인할 수 없는 것(실제로 들리는가, 보이는가)만 최소로 남기고 시작할 때 무엇을 확인해야 하는지 한 줄 출력한다. 상태, 개수, 순서 같은 논리는 Agent로 확인한다.
- **테스트 폴더는 시험하는 소스 구조를 그대로 따른다.** (`Testing/Runtime/SDLAudio-Test/SDLAudio/Static/`은 `Runtime/SDLAudio/Static`을 시험한다.) User/Agent 폴더는 두지 않는다. 공용은 `Doubles/`(가짜: `Fake...`, `InMemory...`)와 `TestSupport/`(테스트 데이터 만들기)에 둔다. 새 `.cpp`/`.ixx`는 `.vcxproj`와 `.filters`에 폴더와 같은 이름의 필터로 등록한다. Agent 테스트가 읽는 파일은 `Testing/Resource/Agent/<종류>/<형식>/`(예: `Audio/Ogg`, `Image/Png`, `Model/Gltf`) 아래에 작게 만들어 두고(큰 실제 파일은 읽지 않고 같은 형식의 작은 파일로 대신한다), `Testing/Resource/Asset` 같은 User용 리소스는 읽지 않는다.
- **테스트 네임스페이스는 `역할::시험하는 소스 프로젝트 이름 + Project`로 짓는다.** (예: `Agent::SDLAudioProject`, `User::ServiceProject`) 폴더는 네임스페이스에 넣지 않고, 한 테스트 프로젝트에서 같은 역할의 테스트는 한 네임스페이스에 모은다. 테스트 이름이 실제 클래스(`Widget`, `Voice` 등)와 충돌하지 않게 하려는 규칙이다. 같은 모듈의 다른 파일과 이름이 겹치지 않게(모듈 안의 이름은 링크가 겹친다) 파일 안에서만 쓰는 도우미는 이름 없는 네임스페이스에 두고, 여러 파일이 쓰는 도우미는 역할 네임스페이스 바로 아래(`Agent`)에 둔다. `TEST`/`TEST_F`는 네임스페이스 밖에 두어도 된다. 아직 정리하지 않은 테스트 프로젝트(UI, 렌더, 에셋)는 예전 방식(`<폴더 이름>Dir`, 실제 디렉터리 구조와 1:1, 예: `GameDir::WidgetDir`)이 남아 있고, 그 프로젝트를 정리할 때 이 규칙으로 바꾼다.
- **테스트를 위한 접근 확장 금지**: 테스트를 위해 함수를 `public`으로 만들거나 공개(export)하지 않는다. 모듈의 비공개 클래스를 시험할 때는 `export`를 추가하는 대신 테스트 `.cpp`를 대상 모듈의 구현 유닛(`module 대상모듈;`)으로 쓴다.
- **오디오 Agent 테스트는 소리 장치 없이 돈다.** `Test_Audio.bat`이 `SDL_AUDIODRIVER=dummy`를 설정하고, 장치로 나가는 소리가 필요하면 `SDL_SetAudioPostmixCallback`으로 가로채서 크기를 확인한다.
- **테스트 중 남긴 `Core::Logger::Error`는 `Testing/Resource/ErrorLog/<프로젝트>.log`에 파일로만 남는다** (FileAsset, DxInput, SDLAudio, DxRender, UI, UIVisualizer 테스트의 `Main.cpp`가 시작할 때 `Logger::Initialize`를 부른다. 콘솔에는 나오지 않는다). 테스트가 실패하면 원인을 이 파일에서 읽는다. 일부러 오류를 일으키는 테스트는 `Core::ErrorCapture`(`Core.Logger`)를 만들어 그 구간의 Error를 파일 대신 받고, 개수와 문장(`Count()`, `Messages()`)을 확인한다. 그래서 파일에 남은 `[error]`는 예상하지 못한 오류이고 정상이면 `[error]`가 한 줄도 없다 (`UIVisualizer-Test.log`에는 UIVisualizer가 남기는 `[info]`가 있다). 새로 일부러 오류를 내는 테스트도 같은 방식으로 쓴다. 오류 건수를 세려고 테스트를 하나씩 따로 돌리면 누수 의심 재실행 때문에 건수가 두 배로 보일 수 있다.
- **메모리 누수는 테스트마다 검사한다 (Debug, `Test.Runner`의 `LeakCheckListener`).** 테스트가 끝난 뒤에도 해제되지 않은 블록이 있으면 그 테스트가 실패한다. 처음 쓰일 때 만들어지는 정적 객체가 새는 것처럼 보이므로, 의심되는 테스트만 모아 다시 돌려서 두 번째에도 남는 것만 실패로 센다. 블록 내용(크기와 바이트)은 stderr로 나오며 파일과 줄은 알려 주지 않으니 테스트를 하나씩 돌려 좁힌다. `DxRender-Test`도 Agent 테스트는 창 없이 돌므로 이 검사를 켠다 (D3D 누수는 `GlobalEnv(true)`가 따로 보고한다). 옛 T 테스트(`RenderServiceT` 등)는 창을 띄우므로 `Test_Render.bat` 없이 직접 돌리면 의심 테스트를 다시 돌릴 때 창이 또 뜬다. 이것 때문에 지키는 규칙: `SUCCEED()`를 쓰지 않고(gtest가 성공 결과를 끝까지 들고 있어 새는 것으로 보인다), 라이브러리를 정리한 뒤(`SDL_Quit` 등)에는 그 라이브러리 함수를 더 부르지 않는다 (전역 정보가 다시 만들어져 샌다).
- **`DxRender-Test`는 시작할 때 D3D12 디버그 레이어를 켠다 (`Main.cpp`).** 레이어는 프로세스 전체에 적용되므로 시험 순서와 상관없이 모든 시험이 같은 검사를 받는다. D3D12를 잘못 쓰면(힙을 정하기 전의 루트 시그니처, GPU가 쓰는 할당자 해제 등) 레이어가 오류에서 멈춰 시험이 `SEH exception with code 0x87a`로 실패한다. 원인 문장은 `OutputDebugString`으로만 나가서 디버거가 없으면 수신기(DebugView 등)로 읽는다. GPU 기반 검증은 기본으로 꺼져 있고(켜면 전체가 약 3배 느리다) 환경 변수 `STRAWBERRY_GPU_VALIDATION=1`일 때만 켜진다. `Test_Render.bat <필터> gbv`로 켠다 (언제 켜는지는 `render-gpu-validation.md`). 진짜 GPU로 창을 띄우는 옛 T 테스트는 이 검증 아래에서 디버그 레이어 안에서 죽으므로(`Draw_View_Multi`는 접근 위반, `Draw_Text`는 `0x87a`) 직접 실행할 때도 켜지 않는다. **User 테스트(`RenderServiceUser` 등, 진짜 GPU와 보이는 창)는 `Test_Render.bat RenderServiceUser.*`처럼 필터에 `User`를 넣어 돌린다.** 이때 GPU 기반 검증은 `gbv`를 줘도 켜지 않고, `Main.cpp`는 시험별 힙 검사와 의심 시험의 재실행(창이 두 번 뜬다)을 끈다. 종료 때의 CRT 힙 보고와 D3D 객체 보고는 그대로 한다. GPU를 막아 두고 확인하는 시험은 `TestSupport/QueueGate`를 쓰고, 제출한 작업이 끝나기 전에 큐나 목록을 없애지 않는다. 일부러 D3D12 오류를 내는 시험(PSO 생성 실패 등)은 그 시험의 디바이스에서만 `ID3D12InfoQueue::SetBreakOnSeverity(ERROR, FALSE)`로 멈춤을 끈다. 짧은 셰이더가 필요하면 `TestSupport/TestShaders`를 쓴다.
