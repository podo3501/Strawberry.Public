# 테스트 코드 규칙

- **중복 없이 작성한다.** 기존 테스트와 겹치면 공통 부분을 리팩토링하거나 중복된 테스트를 삭제한다.
- **한글 주석**: 각 테스트(`TEST_F` 등) 위에 "무엇을 확인하는 테스트인지" 한글 한두 줄 주석을 단다. 사용자가 테스트 목록을 훑어볼 때 의도를 바로 알 수 있게 하기 위함이다. (CLAUDE.md의 "테스트 언급 금지"는 프로덕션 코드 주석과 커밋 메시지에 대한 규칙이며, 테스트 코드 안의 설명 주석과는 별개다.)
- **수치로 정확히 검증한다.** "뭔가 그려졌다" 같은 느슨한 검증보다 좌표/크기/개수를 정확히 확인한다. 대신 기대값은 규칙에서 계산해서 쓰고(예: `패딩 + 바이트 수 × 글자 폭`), 반복되는 상수는 한 곳에 이름을 붙여 모은다.
- **깨진 테스트의 기대값을 실제 출력에 맞춰 고치지 않는다.** 먼저 코드의 버그인지 의도한 변경인지 구분하고, 의도한 변경일 때만 규칙에 맞게 기대값을 고친다.
- **화면에서 눈으로 보는 확인은 사용자가 한다.** 사용자가 알려 주는 버그는 가능하면 재현하는 테스트를 먼저 추가한 뒤 고친다.
- **테스트 네임스페이스는 `<폴더 이름>Dir`로 짓고, 실제 디렉터리 구조와 1:1로 맞춘다.** 테스트 이름이 실제 클래스(`Widget`, `Toggle` 등)와 충돌하지 않게 하려는 규칙이다. `Testing/Game/`의 테스트는 `GameDir`, 그 아래 `Widget/` 폴더의 테스트는 `GameDir::WidgetDir`처럼 폴더 하나가 네임스페이스 하나다. 기준은 테스트 프로젝트 폴더가 아니라 **테스트가 시작하는 코드의 위치**다. 백엔드(`DxInput`, `DxRender`, `FileAsset`, `SDLAudio`)는 `Game/Service`로 감싸여 있어 테스트가 Service에서 시작하므로, `Testing/Runtime/*-Test`의 테스트도 `GameDir::ServiceDir`를 쓴다 (`RuntimeDir`나 `DxInputDir` 같은 백엔드 이름은 보통 나오지 않는다). Service를 거치지 않고 백엔드 내부를 직접 검사하는 테스트는 그 백엔드 폴더 구조를 따른다 (예: `DxRender`의 그래프 내부 테스트는 `DxRenderDir::GraphDir`). 새 테스트 프로젝트나 폴더를 만들 때도 같은 방식으로 정하고, 폴더를 옮기거나 이름을 바꾸면 네임스페이스도 함께 바꾼다. `TEST`/`TEST_F`는 네임스페이스 밖에 두어도 되며, 헬퍼와 픽스처를 감싸는 네임스페이스에 적용한다.
- **테스트를 위한 접근 확장 금지**: 테스트를 위해 함수를 `public`으로 만들거나 공개(export)하지 않는다.
