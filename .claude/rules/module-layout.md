# .ixx / .cpp 분리 기준

- **기본은 `.ixx` 한 파일에 선언과 구현을 함께 둔다.** 함수가 2-3줄이거나 바로 리턴하는 정도로 짧으면 그대로 둔다 (Core 대부분, `Button`, `Toggle`, `Pressable` 등). 한 파일에 있으면 읽기 쉽고, 거의 바뀌지 않는 파일은 나눌 이유가 작다. 처음부터 `.cpp`를 만들지 않는다.
- **여러 줄의 실제 로직이 생기면 나눈다.** 파일 줄 수보다 함수 내용이 기준이다. 60줄 정도여도 편집/그리기처럼 분기와 반복이 있는 함수가 있으면 나눈다 (`Slider`, `TextBox`). `.ixx`가 바뀌면 그것을 import하는 쪽이 모두 다시 컴파일되므로, 자주 바뀌는 구현은 `.cpp`로 빼는 편이 빌드에도 이롭다.
- 나눈 뒤에는 `.ixx`에 선언과 한 줄짜리 접근자만 남기고, 나머지 구현을 `.cpp`로 옮긴다. 새 `.cpp`는 `.vcxproj`와 `.filters`에 등록한다.
