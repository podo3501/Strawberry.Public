# UI 모듈 (`Game/UserInterface`, 모듈명 `UserInterface`)

- 의존 가능: `Contract.Input.Service`, `Contract.Render.UI`, `Contract.Asset.Shared`(`IAssetStorage`만), `Serialization`, `Core.Math`, `Core.Utils`, `Core.TypeHierarchy`, `Core.AssetPath`. **`DxRender`/`DxInput`에 의존하지 않는다.** 그리기는 `IOverlayView`, 텍스트 측정은 `ITextMeasurer`, 입력은 `MouseState`(순수 데이터)로만 접근한다. 폰트와 스킨은 클라이언트가 주입한다. 저장소도 `IAssetStorage&`를 호출 때마다 인자로 받고, `FileAsset`은 import하지 않는다 (구현체는 툴/클라이언트가 만들어 넘긴다).
- `UserInterface`가 레이어(Hud < Window < Popup < Tooltip)별 위젯 트리를 소유한다. 위쪽 레이어가 입력을 먼저 받는다. 보조 객체: `InputRouter`(hover/캡처/클릭/휠), `FocusRouter`(Tab/키 버블링/문자 입력/모달), `TooltipController`.
- 수명: 부모가 자식을 `unique_ptr`로 소유하고 `Detach`는 소유권을 돌려준다. 라우터는 `weak_ptr` 핸들만 보관한다. **콜백 중에 위젯이 Detach/파괴돼도 안전해야 한다** (전용 테스트가 있다).
- 레이아웃: 위치는 anchor/pivot/offset, 크기는 축별 `SizePolicy`(Fixed/Fit/Fill). 변경 시 `MeasureTree`(아래→위) 후 `ArrangeTree`(위→아래). 컨테이너는 `ArrangeChildren`을 재정의한다. 좌표는 정수 픽셀로 맞춘다.
- 입력 의미: 누름은 위젯에서 부모로 버블링되고 소비한 위젯이 캡처한다. 클릭은 뗀 위치가 그 위젯 위일 때만 성립한다. `Backdrop`은 모달이며 포커스와 키를 가둔다.
- 키와 문자: 키(`OnKeyDown`)는 포커스 위젯에서 부모로 버블되지만, 문자(`OnTextInput`, UTF-8)는 포커스 위젯만 받고 버블되지 않는다. 포커스가 없거나 모달 밖이면 버린다.
- 위젯 파일은 `Widget/{Containers,Controls,Drawing,Foundation}`에 있고 `UserInterface.Widget.ixx`가 묶는다. 새 위젯은 이 구조와 `.vcxproj`(+`.filters`) 등록을 따른다.
- 입력을 한동안 UI에 보내지 않을 때(UIVisualizer 모드)는 `UserInterface::ReleaseInput()`으로 hover, 누름 캡처, 포커스를 풀어 위젯을 평상시 모습으로 돌려놓는다. 풀 때 Leave/Up/Blur는 가지만 클릭은 일어나지 않는다.
- 시간: `UserInterface::Tick(dt)`는 툴팁과 포커스 위젯(`OnTick`)에게 시간을 전달한다. 캐럿 깜빡임처럼 포커스 위젯에만 필요한 갱신이 이 경로를 쓴다.
- **`SetXxx()` 규약**: 프로그램에서 호출하는 `SetXxx()`는 콜백을 발생시키지 않고, 사용자 입력으로 값이 바뀔 때만 `OnChanged` 류가 발생한다 (Toggle, Slider, TextBox 참고).
- 저장/불러오기: `WidgetSerializer`가 트리를 JSON(`{ version, root }`)으로 `IAssetStorage::WriteText/ReadText`에 맡긴다. 위젯이 저장을 지원하려면 `bool Serialize(Serializer&, IWidgetResources&)`(`Widget::Serialize`를 먼저 호출, 실패하면 false)를 구현하고 `WidgetSerializer.cpp`의 표에 한 줄(파일에 적는 이름, `Core::GetTypeID<클래스>()`, 생성 함수) 더한다. 표에는 정확한 클래스를 등록하므로 등록하지 않은 파생 클래스는 부모 이름으로 저장되지 않고 저장이 거부된다. 파일에 적는 이름은 바꾸지 않는다 (`TypeID`는 실행마다 달라질 수 있어 파일에 적지 않는다). 읽을 때 키가 없으면 현재 값을 유지하고, 지원하지 않는 버전이나 모르는 위젯 종류는 불러오기 전체를 실패로 본다. 브러시 같은 런타임 핸들은 파일에 못 적으므로 `IWidgetResources`(이름 <-> 핸들, 클라이언트/툴이 구현)로 이름을 적고 읽는다. 이름을 모르면 저장/불러오기 전체가 실패한다. 단순한 값은 멤버를 `Process`에 직접 넘겨 읽기/쓰기를 같은 코드로 쓰고(`IsWrite` 분기는 읽은 뒤 레이아웃 반영처럼 꼭 필요한 곳만), `Serializer`는 `Serializer::ForRead(json)`와 `Serializer::ForWrite(json)`로 모드를 정해 만든다. 목록과 표는 파일에 키가 있으면 기존 내용을 비우고 파일 값으로 채우고 키가 없으면 그대로 둔다. enum은 `Count`를 마지막에 두고 `Core::EnumToStringMap<T>()` 이름 표를 Serialize를 구현한 `.cpp`에 특수화하면 (다른 `.cpp`에서도 이름이 필요해지면 그때 `.ixx`로 옮긴다) 이름으로 저장된다. 모르는 이름이나 문자열이 아닌 값은 다른 틀린 값처럼 읽기 오류로 남고 기존 값이 유지된다. 쓸 때 이름 표 밖의 값(`InvalidEnum`, `Count`)은 쓸 수 없어 `Error`로 남고 `HasError()`가 참이 되며 `WidgetSerializer`는 저장을 거부한다. 이름 표의 이름은 바꾸지 않는다. 타입이 틀린 값(숫자 자리의 문자열, 담을 수 없는 범위의 정수, 배열 자리의 객체)은 예외 없이 `Error`로 남고 그 값은 건너뛰어 기존 값이 남으며, `Serializer::HasError()`가 참이 된다 (포함하는 클래스와 배열 안의 오류도 바깥 `Serializer`까지 전해진다). `WidgetSerializer::Load`는 `HasError()`면 불러오기 전체를 실패로 본다. 읽은 값의 의미(범위 등)를 `Serialize`에서 검사하면 `serializer.ReportError("이유")`로 같은 방식으로 알린다. 쓸 때 항목이 없는 목록, 표, 키 없는 클래스는 null로 적히므로 읽을 때 빈 값으로 받는다.
- **파일 이름은 `Core::AssetPath`**: `WidgetSerializer`와 `SaveLayer/LoadLayer`, `IAssetStorage`는 파일을 `Core::AssetPath`(저장소 루트 아래 상대 경로)로 가리킨다. 문자열에서 암묵 변환되지 않으므로 `Core::AssetPath::Make("Layout/Window.json")`처럼 명시적으로 만든다. 대소문자는 보존하되 비교와 해시는 무시하고, 절대 경로와 저장소 밖으로 나가는 `..`는 거부한다 (`TryMake`는 nullopt, `Make`는 Assert).
- **레이어 단위 저장**: `UserInterface::SaveLayer/LoadLayer(layer, storage, resources, filename)`가 레이어 루트(Group)를 `WidgetSerializer`의 형식 그대로 레이어마다 파일 하나로 저장하고 읽는다. `LoadLayer`는 성공하면 그 레이어의 기존 위젯을 모두 버리고 파일의 자식으로 바꾸며, 실패하면(파일이 없거나 깨짐, root가 Group이 아님) 레이어를 그대로 둔다. 불러올 때의 `WidgetLoadContext`는 `UserInterface`가 채운다(측정기, Popup 레이어를 팝업 호스트로). 콜백은 파일에 없으므로 불러온 뒤 다시 단다.
- **위젯 이름**: `Widget::SetName`으로 준다. 이름은 선택이고 비어 있으면 없음이며, 비어 있지 않은 이름은 같은 부모 아래 형제끼리 겹치지 않는다. `/`와 `#`은 쓸 수 없다 (경로 구분자와 이름 없는 위젯의 임시 표기 `종류#순서`). `SetName`은 어기면 바꾸지 않고 false를 돌려준다. `Attach`는 겹침을 막지 못하므로 `WidgetSerializer`가 저장(거부)과 불러오기(전체 실패)에서 한 번 더 검사한다. 이름은 `Widget::Serialize`의 `name` 키로 적고 빈 이름은 키를 적지 않는다. 경로 찾기(`Find`)는 `WidgetInspector`에만 두고, 게임 코드가 이름으로 위젯을 찾아야 할 일이 생기면 그때 공개 여부를 정한다.
- **틴트의 RGB는 sRGB 값이다** (스크린샷이나 포토샵에서 뽑은 색을 /255 한 값을 그대로 적는다). 렌더 백엔드가 그리기 직전에 선형으로 바꿔 곱하며(`Core::Color::SrgbToLinear`) 알파는 바꾸지 않는다. 1을 넘는 값은 밝게 하는 용도다.
- 버튼류(`ButtonBrushes`: Button, Toggle, Dropdown)의 9슬라이스 설정(마진, 원본 크기)은 세 상태가 하나를 함께 쓰므로 세 이미지는 크기와 테두리가 같아야 한다. 9슬라이스일 때만 `sliced`, `sliceLeft/Top/Right/Bottom`, `srcWidth/Height` 키(prefix가 있으면 `offSliced`처럼)를 적고, 키가 없으면 통짜 이미지다.
- 글자를 그리는 위젯의 저장은 `TextSerialize`(폰트 이름, 렌더 모드, 레이아웃, 색과 효과 5개)를 재사용한다. 폰트도 브러시처럼 `IWidgetResources`의 이름으로 적는다. `UserInterface`는 `ITextMeasurer&`를 생성자로 받아 보관하고(`TextMeasurer()`), 위젯을 불러올 때(`WidgetSerializer::Load`)만 측정기가 필요하다. 불러올 때 필요한 실행 중 참조(측정기, `Dropdown`이 목록을 펼칠 팝업 레이어)는 `WidgetLoadContext`로 묶어 넘긴다. 새 위젯이 다른 서비스가 필요하면 이 구조체에 필드를 더한다. 줄바꿈 폭(`Text::m_wrapWidth`)처럼 생성 때 고정되는 값은 크기와 따로 저장한다.
- **위젯 타입은 `Core.TypeHierarchy`로 알아본다 (`dynamic_cast` 금지).** `Widget`은 `Core::TypeRoot<Widget>`을, 나머지 위젯은 `Core::TypeNode<자기, 부모>`를 상속한다 (예: `class Button : public Core::TypeNode<Button, Pressable>`). 새 위젯을 만들 때도 같은 형태로 쓰고, **`Derived` 자리에 반드시 자기 이름을 쓴다** (복사해서 만들 때 이전 이름이 남으면 그 위젯으로 `Core::Cast`할 때 `static_assert`로 컴파일 오류가 난다). 생성자에서 부모를 부를 때는 `TypeNode(...)`라고 쓴다 (부모 이름 대신 상속한 `TypeNode`의 주입된 클래스 이름). 위젯에서 하위 타입으로 바꿀 때는 `Core::Cast<Toggle>(widget)`를 쓴다.
